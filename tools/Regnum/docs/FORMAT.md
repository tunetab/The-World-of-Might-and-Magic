Справочник по файлам мира Regnum для людей и агентов, которые читают и правят JSON вручную. Код — `src/core/io*`, модель данных — `src/core/world.h`, перечисления и пределы — `src/core/schema.cpp`. Архитектура — [ARCHITECTURE.md](ARCHITECTURE.md), формулы — [RULES.md](RULES.md).

## 1. Коротко для правки вручную

1. Мир — папка с `world.json` и `data/*.json` (или архив `.regnum` с той же раскладкой). Каждая таблица — отдельный файл.
2. Кодировка UTF-8 (BOM допускается), переводы строк LF. Порядок ключей и отступы при чтении не важны: файл получит канонический вид (раздел 3.1), когда редактор в следующий раз запишет его таблицу.
3. Ссылки — строки с префиксом вида: `"p12"` — провинция 12, `"f3"` — фракция 3 (таблица в разделе 3.3). Пустая ссылка — `null`.
4. Новую запись добавляйте с ID = `meta.seq.<вид> + 1` и увеличьте этот счётчик в `world.json`. Запись без `id` тоже читается: ей назначается новый ID (с предупреждением).
5. После правки запустите проверку: `regnum-cli validate <папка мира>` (раздел 13). Код возврата 0 — мир в порядке.
6. Ошибочные значения не роняют редактор: при чтении они исправляются (раздел 11), а каждое исправление попадает в список предупреждений с указанием файла и места (`data/provinces.json: p12.owner: нет фракции f9 — владелец удалён`). Исправленный мир записывается при следующем сохранении.
7. Не правьте файлы, пока мир открыт в редакторе и в нём есть несохранённые изменения: редактор заметит внешнее изменение (раздел 9) и предложит перечитать мир, но несохранённая работа в редакторе и ваша правка в одном файле не объединяются.

```
    modifiers.json           модификаторы (наборы эффектов)

    techs.json               технологии (деревья фракций)

    routes.json              торговые маршруты
```

## 3. Общие правила

### 3.1 Запись файлов

Редактор пишет файлы так, чтобы диффы в Git были минимальными:

- JSON с отступом 2 пробела; ключи объектов отсортированы по байтам UTF-8 на всех уровнях;
- записи таблиц — по возрастанию ID; элементы списков внутри записи — в порядке, заданном пользователем;
- массив из одних скаляров (`["m1", "m2"]`, `[210.5, 300.25]`) — в одну строку;
- `data/geo.json` и `data/relations.json` — одна запись на строку (компактно, ключи отсортированы);
- перевод строки LF, в конце файла — перевод строки;
- каждое поле записывается всегда, даже со значением по умолчанию (кроме эффектов модификатора: только заданные);
- запись атомарная: временный файл и замена; `world.json` пишется последним.

Сохраняются только файлы изменённых таблиц и отсутствующие на диске файлы. Файл, содержимое которого совпадает с новым, не перезаписывается.

### 3.2 Числа

- Числа JSON — double. Целые записываются без дробной части, остальные — кратчайшим точным десятичным представлением (`0.3`, `15000.5`).
- Координаты карты (узлы, точки дуг, войска, маршруты) и положения на схемах деревьев (`pos` построек и технологий) округляются при записи до 0,01.
- Целочисленные поля (численности, население, ходы, уровни) — целые; дробное значение округляется с предупреждением. Число, записанное строкой (`"12"`, `"1 200,5"`), принимается с предупреждением.
- `NaN` и бесконечности в JSON не записываются; нечисловое значение заменяется значением по умолчанию.
- Система координат карты — пиксели исходного изображения 8000 × 4500, ось Y направлена вниз. Точки вне карты переносятся на край.

### 3.3 Идентификаторы и ссылки

ID — целое > 0, у каждого вида своя последовательность (`meta.seq`). Удалённые ID не используются повторно. В файлах ID и ссылки записываются строкой с префиксом вида:

| Вид | Префикс | Пример | Счётчик в `meta.seq` |
| --- | --- | --- | --- |
| провинция | `p` | `p12` | `province` |
| фракция (государство или гильдия) | `f` | `f3` | `faction` |
| персонаж | `c` | `c7` | `character` |
| модификатор | `m` | `m2` | `modifier` |
| постройка | `b` | `b5` | `building` |
| технология | `t` | `t9` | `tech` |
| войско или флот | `a` | `a4` | `army` |
| торговый маршрут | `r` | `r1` | `route` |
| сделка | `d` | `d2` | `deal` |
| запись хроники | `l` | `l100` | `log` |
| строка армии или флота фракции | `u` | `u3` | `row` |
| место в совете фракции | `k` | `k1` | `council` |
| ресурс | `rs` | `rs2` | `resource` |
| раса | `rc` | `rc1` | `race` |
| культура | `cu` | `cu1` | `culture` |
| религия | `rl` | `rl2` | `religion` |
| форма правления | `gv` | `gv1` | `government` |
| должность | `po` | `po1` | `position` |
| узел геометрии | — | `17` | `node` |
| дуга геометрии | — | `40` | `edge` |

- Чтение принимает и число (`12`), и строку из цифр (`"12"`). Префикс другого вида — ошибка ссылки (`"p3"` там, где ожидается фракция, удаляется с предупреждением).
- Пустая ссылка — `null` (при чтении также `0` и `""`).
- Строки армии и флота (`u`) — общая последовательность всего мира: ID строки уникален среди всех фракций. Места в совете (`k`) — тоже.
- `rs1` — встроенный ресурс «Золото»: запас золота фракции и есть её казна.

### 3.4 Перечисления

Записываются строковыми идентификаторами. Неизвестное значение заменяется значением по умолчанию (первым в списке, если не указано иное) с предупреждением, где перечислены допустимые варианты.

| Поле | Значения (по умолчанию — **жирным**) |
| --- | --- |
| `Province.size` | `small` (1 слот), **`medium`** (2), `large` (3) |
| `Province.city` | `outpost`, **`village`**, `town`, `city` |
| `Faction.kind` | **`state`** — государство, `guild` — торговая гильдия |
| `ArmyRow.type` (строка армии) | **`light_inf`**, `medium_inf`, `heavy_inf`, `light_cav`, `medium_cav`, `heavy_cav`, `flying`, `casters`, `ranged`, `beasts`, `monsters`, `machines` |
| `FleetRow.type` (строка флота) | `ship_line` — линкор, **`frigate`** — фрегат, `galleon` — торговый галеон |
| `Relation.s` | `war` — война, `alliance` — союз, `neutral` — статус-кво, **`unknown`** — незнакомы |
| `Building.cat` | `military`, **`economic`**, `industrial`, `residential` |
| `Army.kind` | **`army`** — войско, `fleet` — флот |
| `Deal.kind` | **`trade`** — сделка, `tribute` — дань, `reparations` — репарации |
| `DealItem.from` | **`a`**, `b` — какая сторона отдаёт |
| `DealItem.mode` | **`once`** — разово, `turn` — каждый ход |
| `Deal.status` | **`active`**, `done`, `cancelled` |
| `LogEntry.kind` | `turn`, `economy`, `build`, `tech`, `war`, `battle`, `army`, `fleet`, `diplomacy`, `trade`, `province`, `guild`, `population`, **`note`** |
| `Flag.pattern` | **`solid`**, `h2`, `h3`, `v2`, `v3`, `cross`, `saltire`, `quarters`, `bend`, `chevron`, `border`, `canton`, `chief`, `pale` |
| `Settings.occupiedIncome` | **`owner`** — владельцу, `occupier` — оккупанту, `none` — никому |
| `Edge.kind` | **`border`** — граница, `coast` — берег, `frame` — рамка карты |
| `Edge.tl`, `Edge.tr` | `none` — вне карты, **`land`** — суша, `sea` — море |

### 3.5 Цвета, двоичные данные, строки

- Цвет — `"#rrggbb"` (строчные шестнадцатеричные цифры). Полупрозрачный цвет — `"#rrggbbaa"`. При чтении допускается и `"#rgb"`.
- Двоичные данные (изображение флага, портрет) — строка base64 (стандартный алфавит, дополнение `=`). При чтении пробелы и переводы строк внутри base64 пропускаются, допускается data URI `"data:image/png;base64,..."`.
- Текст — любые символы Юникода (кириллица, эмодзи). Переводы строк внутри текста — экранированные `\n`.

### 3.6 Пропуски и неизвестные поля

- Отсутствующее поле или `null` — значение по умолчанию (указано в таблицах ниже).
- Неизвестное поле отбрасывается с предупреждением «неизвестное поле отброшено» (опечатки в именах полей видны сразу).
- Значение неверного типа (строка вместо массива и т. п.) — поле пропускается с предупреждением.
- Элемент массива записей, не являющийся объектом, пропускается.

```json
    "basemap": "wmm-expanded-v1",

            "government": 6, "log": 5, "modifier": 2, "node": 4, "position": 6, "province": 3, "race": 2,

  },
  "settings": {
    "autosaveFolder": true,

```

| Поле | Тип | По умолчанию | Смысл и пределы |
| --- | --- | --- | --- |
| `format` | строка | — | всегда `"regnum-world"`; иное значение — отказ «это не мир Regnum» |
| `version` | число | 1 | старшая версия формата (раздел 12) |
| `meta.name` | строка | «Новый мир» | название мира |

| `meta.turn` | целое | 1 | текущий ход, 1…1 000 000 |
| `meta.seq.<вид>` | целое ≥ 0 | 0 | последний выданный ID вида (раздел 3.3); не меньше наибольшего ID в данных |
| `meta.basemap` | строка | `wmm-expanded-v1` | идентификатор базовой карты (манифест `assets/basemap`) |
| `meta.notes` | строка | `""` | заметки |
| `settings.fillOpacity` | число | 0.5 | непрозрачность заливки провинций, 0…1 |
| `settings.labelStates`, `labelProvinces`, `labelArmies` | логическое | `true` | подписи государств, провинций, войск на карте |
| `settings.occupiedIncome` | перечисление | `owner` | кому идёт доход оккупированной провинции |
| `settings.rebellionRoll` | логическое | `false` | бросок восстания в конце хода |
| `settings.autosaveFolder` | логическое | `true` | автосохранение в папку проекта |
| `settings.autosaveSec` | целое | 60 | период автосохранения, 10…3600 с |

## 5. data/catalogs.json — справочники

Шесть списков: `resources`, `races`, `cultures`, `religions`, `governments`, `positions`. Порядок элементов сохраняется (это порядок в интерфейсе).

```json
{
  "resources": [
    {"builtin": true, "color": "#e2b33c", "icon": "coins", "id": "rs1", "name": "Золото"},
    {"builtin": false, "color": "#d9c36b", "icon": "grain", "id": "rs2", "name": "Зерно"}
  ],
  "races": [], "cultures": [], "religions": [], "governments": [], "positions": []
}
```

| Поле | Тип | По умолчанию | Смысл |
| --- | --- | --- | --- |
| `id` | ссылка своего вида (`rs`, `rc`, `cu`, `rl`, `gv`, `po`) | новый ID | уникален в списке |
| `name` | строка | `""` | название |
| `color` | цвет | `#888888` | цвет на карте и в диаграммах |
| `icon` | строка | `""` | имя значка |
| `builtin` | логическое | `false` | встроенный элемент (не удаляется в интерфейсе) |

`rs1` («Золото», казна) существует всегда: если его нет, он добавляется при чтении.

## 6. data/geo.json — геометрия

Плоский граф провинций: узлы и дуги. Дуга — полилиния `a → pts… → b`. Стороны дуги помечены провинцией (`pl` — слева, `pr` — справа по ходу от `a` к `b`) и рельефом (`tl`, `tr`). Грань графа — часть провинции; провинция может состоять из нескольких граней (острова). Береговые дуги (`coast`) и рамка карты (`frame`) создаются из береговой линии базовой карты и в редакторе не двигаются.

```json
{
  "edges": [
    {"a":1,"b":2,"id":1,"kind":"frame","pl":null,"pr":null,"pts":[],"tl":"sea","tr":"none"},
    {"a":5,"b":6,"id":5,"kind":"coast","pl":"p3","pr":"p8","pts":[5573.5,20.18,5622.5,28.24],"tl":"land","tr":"sea"}
  ],
  "nodes": [
    [1,0,0],
    [2,8000,0]
  ]
}
```

| Поле | Формат | Смысл |
| --- | --- | --- |
| `nodes[i]` | `[id, x, y]` | узел: ID (число без префикса) и координаты |
| `edges[i].id` | число | ID дуги |
| `edges[i].a`, `b` | число | ID начального и конечного узла |
| `edges[i].pts` | `[x1, y1, x2, y2, …]` | промежуточные точки (без `a` и `b`); при чтении допускаются и пары `[[x1, y1], …]` |
| `edges[i].kind` | перечисление | `border`, `coast`, `frame` |
| `edges[i].pl`, `pr` | ссылка `p` или `null` | провинции слева и справа; `null` — не назначено |
| `edges[i].tl`, `tr` | перечисление | рельеф слева и справа: `land`, `sea`, `none` (вне карты) |

Правка геометрии вручную возможна, но корректность графа (без пересечений, замкнутые грани, согласованные метки сторон) проверяет только `regnum-cli validate`; надёжнее править границы в редакторе.

## 7. Таблицы сущностей

Каждая таблица — объект с одним массивом записей: `{"provinces": [ {...}, {...} ]}`. Ниже для каждого поля: тип, значение по умолчанию (если поля нет) и правило нормализации.

### 7.1 data/provinces.json

```json
{
  "provinces": [
    {
      "baseTrade": 250,
      "buildings": [{"building": "b1", "constructing": true, "left": 3, "level": 2, "paid": {"rs1": 300, "rs4": 80}, "payer": "f1"}],
      "capital": "Арденбург",
      "city": "city",
      "contentment": -12.5,
      "culture": "cu1",
      "entity": "PRV-0001",
      "garrison": [{"count": 200, "row": "u1"}],
      "hqs": ["f2"],
      "id": "p1",
      "influence": [{"guild": "f2", "pct": 35.5}],
      "localTax": -2.5,
      "lord": "c1",
      "modifiers": ["m1", "m2"],
      "name": "Арден",
      "notes": "",
      "occupied": false,
      "occupier": null,
      "owner": "f1",
      "races": [{"pop": 120000, "race": "rc1"}],
      "religion": "rl2",
      "resource": "rs2",
      "resourceAmount": 40.5,
      "sea": false,
      "size": "large"
    }
  ]
}
```

| Поле | Тип | По умолчанию | Правило |
| --- | --- | --- | --- |
| `id` | `p…` | новый ID | |
| `name` | строка | `""` | название провинции |
| `owner` | `f…` или `null` | `null` | только государство; гильдия или несуществующая фракция — владелец удаляется |
| `lord` | `c…` или `null` | `null` | персонаж-лорд |
| `sea` | логическое | `false` | морская провинция (без хозяйства и заливки) |
| `capital` | строка | `""` | название столицы |
| `size` | перечисление | `medium` | величина (слоты построек) |
| `city` | перечисление | `village` | тип поселения |
| `resource` | `rs…` или `null` | `null` | ресурс справочника |

## 8. Резервные копии

Перед перезаписью файла его прежняя версия кладётся в `.regnum-backup/` с той же вложенностью: `.regnum-backup/data/provinces.000012.json`, `.regnum-backup/world.000003.json`. Номер растёт; хранятся последние 5 версий каждого файла. Версии, записанные автосохранением в папку мира, при перезаписи кладутся в отдельную очередь `.regnum-backup/auto/` (тоже 5 версий), поэтому частые автосохранения не вытесняют копию версии, сохранённой вручную. В папке лежит `.gitignore` со строкой `*` — копии не попадают в Git. Восстановление — заменить файл мира копией и перечитать мир.

## 9. Внешние изменения

При чтении и сохранении редактор запоминает для каждого файла мира размер, время изменения и CRC-32 содержимого. Файл считается изменённым другой программой, если изменились размер или время и при этом изменилось содержимое (перезапись тем же текстом изменением не считается). Изменённые, удалённые и появившиеся файлы показываются пользователю с предложением перечитать мир. Сохранение поверх файла, изменённого извне, требует явного подтверждения: Ctrl+S предлагает «Перечитать», «Сохранить с заменой» или «Отмена»; автосохранение в папку такие файлы не перезаписывает. Архив `.regnum` отслеживается целиком так же (размер, время и CRC-32 файла архива).

## 10. История ходов, архив, данные пользователя

### 10.1 Снимки ходов

`history/turn-NNNN-SSSSSS.json.gz` (NNNN — номер хода, не меньше четырёх цифр; SSSSSS — номер снимка, уникальный в истории мира) — весь мир на момент хода в одном документе, сжатом gzip. Снимки не заменяют друг друга; редактор создаёт три вида снимков:

- `start` — начало хода: мир сразу после расчёта прошлого хода (или при первом открытии мира на этом ходу). К нему ведёт «Начать ход заново».
- `end` — конец хода: мир перед расчётом. Его открывают «Посмотреть» и «Вернуться к ходу» для прошлых ходов.
- `branch` — состояние перед возвратом к другому ходу (брошенная ветвь, к ней можно вернуться).

Новые снимки хранятся в памяти редактора и записываются в `history/` только при сохранении мира (вручную или автосохранением в папку); «Не сохранять» отбрасывает их вместе с миром. Время `at` — время создания снимка, оно сохраняется при сохранении, «Сохранить как» и преобразовании. При сохранении мира в чужую папку или поверх чужого архива история места заменяется историей этого мира. Документ снимка:

```json
{
  "files": {
    "data/catalogs.json": { …содержимое файла… },
    "data/geo.json": { … },
    …
    "world.json": { … }
  },
  "format": "regnum-snapshot",
  "version": 1
}
```

Каждый член `files` — то же значение, что в одноимённом файле проекта, поэтому снимок читается тем же кодом с той же нормализацией.

`history/index.json` — список снимков по возрастанию хода, затем номера, и `head` — номер снимка, от которого идёт сохранённый мир (по нему редактор находит начало и конец ходов текущей ветви):

```json
{
  "head": 15,
  "snapshots": [
    {"at": "2026-10-01T20:00:00Z", "file": "turn-0007-000014.json.gz", "kind": "end", "label": "Ход 7", "name": "Мир Ардена", "parent": 13, "seq": 14, "size": 48211, "turn": 7},
    {"at": "2026-10-01T20:00:01Z", "file": "turn-0008-000015.json.gz", "kind": "start", "label": "Начало хода 8", "name": "Мир Ардена", "parent": 14, "seq": 15, "size": 48390, "turn": 8}
  ]
}
```

`parent` — предыдущий снимок той же ветви: у начала хода — конец прошлого хода, у конца хода и состояния перед возвратом — снимок, от которого шёл мир. Если `index.json` потерян или в нём нет файла, снимки находятся по именам (без подписи и вида). Снимки прежнего формата `turn-NNNN.json.gz` (без номера, один на ход) читаются: «Снимок того же хода заменяет прежний» действует только для них.

### 10.2 Архив .regnum

Обычный zip с той же раскладкой: `world.json` (первым), `data/*.json`, `history/`. Мир может лежать и в единственной вложенной папке архива (`Мир/world.json`) — так получается при упаковке папки целиком. Запись архива атомарная; при сохранении архива его история ходов сохраняется (и дополняется несохранёнными снимками), а при записи другого мира поверх архива его прежняя история удаляется. Преобразование папки и архива — `regnum-cli convert`.

### 10.3 Данные пользователя

Папка данных пользователя: Windows `%APPDATA%/Regnum`, Linux `$XDG_CONFIG_HOME/regnum` или `~/.config/regnum`, macOS `~/Library/Application Support/Regnum`.

- `recent.json` — недавние проекты: `{"recent": [{"at": …, "name": …, "path": …}]}`, новые первыми, не больше 12.
- `autosave/autosave-<слот>.json.gz` — автосохранение мира (документ снимка, раздел 10.1) для восстановления после сбоя; `autosave/autosave-<слот>.json` — сведения: `{"at", "name", "project", "turn"}`. Слот — 16 шестнадцатеричных цифр хеша полного пути проекта или `new` для несохранённого мира. Одному проекту соответствует один слот. Восстановление предлагается (на экране запуска и при открытии мира), если автосохранение новее последнего сохранения мира — `meta.updatedAt` в `world.json` (если его нет — время файла). Сохранение мира удаляет автосохранение его слота.

## 11. Нормализация при чтении

После чтения мир приводится к инвариантам схемы. Каждое исправление — предупреждение `файл: место: что исправлено`; таблицы с исправлениями переписываются при следующем сохранении. Нормализация идемпотентна: повторный проход по исправленному миру ничего не меняет.

1. **Ссылки.** Ссылка на несуществующую запись обнуляется (одиночная) или удаляется (в списке). Исключение — хроника (раздел 7.11).
2. **Пределы.** Числа вне пределов прижимаются к границе, нечисловые заменяются значением по умолчанию (пределы — в таблицах разделов 4–7).
3. **Повторы.** Повторы в списках ссылок удаляются; повторы строк гарнизона, отрядов, рас, влияния складываются; повторная постройка провинции удаляется.
4. **ID.** Запись без ID или с повторным ID получает новый ID. Повтор ID строки армии или места совета в другой фракции получает новый ID; ссылки этой фракции (гарнизоны её провинций, её отряды в войсках) переводятся на новый ID.
5. **Счётчики.** `meta.seq.<вид>` не меньше наибольшего ID вида (иначе поднимается).
6. **Справочники.** `rs1` «Золото» всегда есть и отмечен встроенным.
7. **Провинции.** Владелец — только государство; оккупант — государство, отличное от владельца; гарнизон — строки армии владельца; штабы — до 5 гильдий; сумма влияния гильдий ≤ 100 % (пропорциональное уменьшение); уплаченное за строительство — только у строящейся постройки, плательщик — государство.
8. **Фракции.** У государства нет `homeState` и `stateGuild`; `homeState` гильдии — государство; флаг-изображение — только PNG.
9. **Деревья.** Требования построек и условия технологий без циклов; условия технологии — в дереве той же фракции; технология без фракции удаляется; изученная технология с неизученным условием теряет изученность; уникальная постройка гильдии становится общей.
10. **Войска.** Отряды — строки своей фракции (армии для войска, флота для флота); герой — не больше чем в одном войске; войско без групп удаляется; положение — в пределах карты.
11. **Маршруты и сделки.** Маршрут без двух точек удаляется; сделка без двух различных сторон удаляется.
12. **Геометрия.** Узел с нечисловыми координатами удаляется, точки вне карты переносятся на край; дуга с несуществующим узлом или вырожденная петля удаляется; ссылки дуг на провинции проверяются. Топология графа (пересечения, замкнутость граней) нормализацией не исправляется — её проверяет `regnum-cli validate`.

Чтение отказывает (сообщение по-русски, мир не открывается) только если: нет `world.json`; файл не является корректным JSON (указываются файл, строка и столбец); `format` не `regnum-world`; версия формата новее поддерживаемой; архив повреждён.

## 12. Версии формата

`version` в `world.json` и в снимках — старшая версия формата, сейчас 1. Дробная часть (`1.4`) — младшая версия: файлы того же старшего номера читаются (неизвестные поля отбрасываются с предупреждением). Мир с большей старшей версией не открывается: «Мир сохранён более новой версией Regnum… Обновите редактор». Несовместимые изменения формата увеличивают старшую версию; редактор читает все прежние версии и сохраняет в текущей.

## 13. Командная строка

`regnum-cli` (собирается `tools/Regnum/build.sh regnum-cli`, лежит в `tools/Regnum/bin/<ОС>/`). Путь мира — папка, её `world.json` или архив `.regnum`.

| Команда | Действие | Код возврата |
| --- | --- | --- |
| `validate <мир> [--json] [--strict]` | читает мир, выводит исправления нормализации (раздел 11), ошибки геометрии, файлы, которые будут переписаны при сохранении, и файлы не в каноническом виде | 0 — ошибок нет; 1 — мир не читается или есть ошибки геометрии (с `--strict` — и при любых исправлениях) |
| `inspect <мир> [--json]` | сводка: ход, число сущностей, казна фракций, провинции по владельцам, снимки ходов | 0; 1 — мир не читается |
| `convert <откуда> <куда> [--force]` | папка → архив или архив → папка (по расширению назначения) с историей ходов; мир читается с нормализацией | 0; 1 — ошибка |
| `new <папка или файл.regnum> [--name=…] [--basemap=<папка>] [--no-geometry] [--force]` | новый мир со справочниками по умолчанию и геометрией из береговой линии базовой карты (по умолчанию `tools/Regnum/assets/basemap`) | 0; 1 — ошибка |

`validate --json` выводит объект `{"ok", "path", "bundle", "name", "turn", "errors": [{"code", "msg", "at": [x, y]}], "warnings": [{"file", "where", "msg"}], "rewrite": [файлы с исправлениями], "reformat": [файлы не в каноническом виде]}`; при ошибке чтения — `{"ok": false, "errors": [{"code": "load", "msg"}]}`. `inspect --json` — объект со счётчиками (`counts`), фракциями (`factions`: `id`, `kind`, `name`, `treasury`, `provinces` или `hqs`, `armies`), `provincesByOwner` и `history`.
