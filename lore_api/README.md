# Lore API для ChatGPT

---
type: technical_readme
status: active
canon_level: support
updated_real_date: 2026-05-16
---

Эта папка нужна, чтобы ChatGPT мог получать лор, карточки персонажей и ссылки на портреты из этого репозитория через отдельный API.

Проще говоря: репозиторий остается главным хранилищем канона, а Lore API становится удобным "окошком" для ChatGPT. Вместо того чтобы загружать в чат все файлы сразу, ChatGPT сможет спросить: "дай карточку Михаэля", "найди контекст по Белой Гавани", "дай портретные референсы Картоса".

Важно про изображения: Lore API не прикрепляет PNG/JPG к генератору. Он отдает метаданные референсов и ссылки. Для максимальной похожести лиц Custom GPT должен попросить пользователя открыть ссылку на портрет и прикрепить этот портрет в чат как изображение.

## Что уже работает

- поиск по Markdown-файлам проекта;
- выдача карточки персонажа по имени;
- выдача метаданных основного портрета, промпта портрета и ссылок на файлы;
- выдача `download_url` через временный Lore API/ngrok без GitHub-авторизации;
- подбор контекста сцены по персонажам и локации;
- endpoint `/openapi.json` для подключения как ChatGPT Action;
- ручная пересборка индекса через `/reindex`.

Это не меняет канон и не редактирует сюжетные файлы. API только читает проект и собирает поисковый индекс.

API кэширует повторяющиеся запросы в памяти процесса. Если Custom GPT несколько раз спросит одного и того же персонажа или те же references, сервер отдаст готовый ответ из кэша. Кэш очищается при `/reindex` и при перезапуске сервера.

## Важная идея

Источник истины:

```text
Markdown-файлы репозитория
```

Временный поисковый индекс:

```text
lore_api/.data/lore_index.sqlite3
```

Если лор изменился, нужно просто пересобрать индекс. Ничего вручную в базе править не надо.

## Что нужно установить один раз

Нужны три вещи:

- Python 3.9 или новее - чтобы запускать Lore API;
- PowerShell - чтобы запускать проектные проверки из папки `tools`;
- ngrok - чтобы временно дать ChatGPT публичный HTTPS-адрес к локальному API.

На macOS проще всего поставить все через Homebrew:

```bash
brew install python powershell ngrok
```

Если Python уже установлен, повторно ставить его не обязательно.

Проверить Python:

```bash
python3 --version
```

Проверить PowerShell:

```bash
pwsh --version
```

Проверить ngrok:

```bash
ngrok version
```

Если команды показывают версии, можно идти дальше.

Для ngrok еще нужно один раз зайти на сайт, создать аккаунт и взять authtoken:

```text
https://ngrok.com
```

Токен добавляется командой:

```bash
ngrok config add-authtoken ТВОЙ_ТОКЕН
```

## Первый запуск на этом компьютере

Открой терминал и выполни команды по очереди.

1. Перейти в папку проекта:

```bash
cd /Users/sergeipanov/The-World-of-Might-and-Magic
```

2. Создать отдельное окружение для API:

```bash
python3 -m venv lore_api/.venv
```

3. Включить это окружение:

```bash
source lore_api/.venv/bin/activate
```

После этого в начале строки терминала обычно появляется `(.venv)`.

4. Установить зависимости:

```bash
pip install -r lore_api/requirements.txt
```

5. Собрать поисковый индекс:

```bash
python -m lore_api.indexer
```

Нормальный результат выглядит примерно так:

```json
{
  "documents": 361,
  "chunks": 2442,
  "references": 157,
  "db_path": "/Users/sergeipanov/The-World-of-Might-and-Magic/lore_api/.data/lore_index.sqlite3"
}
```

Числа могут немного отличаться, если в проекте появились новые файлы.

6. Запустить API:

```bash
uvicorn lore_api.app:app --host 127.0.0.1 --port 8010
```

Пока эта команда работает, API доступен на этом компьютере по адресу:

```text
http://127.0.0.1:8010
```

Чтобы остановить API, нажми `Ctrl+C` в этом же окне терминала.

## Проверка, что все работает

Открой в браузере:

```text
http://127.0.0.1:8010/health
```

Если все хорошо, появится что-то вроде:

```json
{"status":"ok","index_exists":true}
```

Еще полезные адреса для проверки:

```text
http://127.0.0.1:8010/search?q=Михаэль%20Белая%20Гавань
http://127.0.0.1:8010/characters/Принц%20Михаэль
http://127.0.0.1:8010/references/Принц%20Михаэль
http://127.0.0.1:8010/scene-context?characters=Принц%20Михаэль,Капитан%20Картос&location=Белая%20Гавань
http://127.0.0.1:8010/openapi.json
```

В адресах `%20` означает пробел.

## Как пользоваться каждый следующий раз

Если окружение уже создано и зависимости установлены, обычно достаточно:

```bash
cd /Users/sergeipanov/The-World-of-Might-and-Magic-Fork
source lore_api/.venv/bin/activate
python -m lore_api.indexer
uvicorn lore_api.app:app --host 127.0.0.1 --port 8010
```

Команда `python -m lore_api.indexer` нужна, чтобы API видел свежие изменения в Markdown-файлах.

## Что значит каждый адрес API

`/health`

Проверяет, жив ли сервер и есть ли индекс.

`/search?q=...`

Ищет по лору. Подходит для общих вопросов вроде "Михаэль Белая Гавань", "Герхард Стокхолд", "Тар-Элам Вито".

`/characters/{name}`

Возвращает карточку персонажа, метаданные, важные куски текста и референсы.

Пример:

```text
/characters/Принц%20Михаэль
```

`/references/{character}`

Возвращает визуальные референсы персонажа: основной портрет, дополнительные портреты, промпт портрета.

В каждом референсе обычно есть:

```json
{
  "type": "portrait",
  "path": "11_Медиа/Портреты_персонажей/Принц_Михаэль/portrait.png",
  "url": "https://random-name.ngrok-free.app/files/...",
  "download_url": "https://random-name.ngrok-free.app/files/...",
  "priority": "primary",
  "description": "Основной портрет персонажа"
}
```

`url` / `download_url` - временная ссылка через запущенный Lore API и ngrok. Она не требует авторизации GitHub, пока сервер и ngrok работают.

Самый простой временный вариант без авторизации GitHub - использовать `download_url`: открыть ссылку, скачать или скопировать изображение и прикрепить его в чат.

`/scene-context`

Собирает контекст для сцены по персонажам и локации.

Пример:

```text
/scene-context?characters=Принц%20Михаэль,Капитан%20Картос&location=Белая%20Гавань
```

`/reindex`

Пересобирает индекс. Это удобно, если API уже запущен, а файлы проекта изменились.

`/openapi.json`

Техническое описание API. Именно этот адрес нужен для ChatGPT Actions.

## Как сделать API доступным для ChatGPT

ChatGPT не сможет обратиться к адресу на твоем компьютере:

```text
http://127.0.0.1:8010
```

Этот адрес виден только самому компьютеру, где запущен сервер. Для ChatGPT нужен публичный HTTPS-адрес, например:

```text
https://lore-api.example.com
```

Для временного режима "развернул, нагенерил, выключил" самый простой рабочий способ - ngrok. Он дает временный публичный HTTPS-адрес к локальному серверу.

### Каждый раз перед генерацией

Открой первый терминал и запусти Lore API:

```bash
cd /Users/sergeipanov/The-World-of-Might-and-Magic
source lore_api/.venv/bin/activate
python -m lore_api.indexer
uvicorn lore_api.app:app --host 127.0.0.1 --port 8010
```

Оставь этот терминал открытым.

Открой второй терминал и запусти ngrok:

```bash
ngrok http 8010
```

В окне ngrok появится строка `Forwarding`. Нужен адрес, который начинается с `https://`.

Он будет выглядеть примерно так:

```text
https://random-name.ngrok-free.app
```

Для Custom GPT нужен адрес схемы:

```text
https://random-name.ngrok-free.app/openapi.json
```

Именно его вставляй в Actions.

Важно: путь должен быть именно `/openapi.json`. Не `/openai.json`.

### Как проверить адрес ngrok

Открой в браузере:

```text
https://random-name.ngrok-free.app/health
```

Если все работает, появится ответ:

```json
{"status":"ok","index_exists":true}
```

### Что вставить в Custom GPT Actions

```text
Schema URL: https://random-name.ngrok-free.app/openapi.json
```

Authentication можно оставить выключенной.

Если ChatGPT пишет `Не удалось найти действительный URL в servers`, проверь две вещи:

1. В адресе должно быть `/openapi.json`, не `/openai.json`.
2. Открой этот же адрес в браузере. В JSON должен быть блок `"servers"` с твоим ngrok-адресом.

### Как выключить

Когда генерация закончена:

1. В терминале с ngrok нажми `Ctrl+C`.
2. В терминале с `uvicorn` нажми `Ctrl+C`.

После этого временный HTTPS-адрес перестанет работать. В следующий раз ngrok может выдать другой адрес, и его нужно будет снова вставить в Custom GPT Action.

## Как создать личный Custom GPT

Обычный чат ChatGPT не умеет напрямую подключать произвольный API по OpenAPI-схеме. Для этого нужен личный Custom GPT.

Создать его можно в веб-версии ChatGPT. В мобильном приложении GPT можно использовать, но обычно нельзя полноценно создавать и настраивать.

1. Открой:

```text
https://chatgpt.com/gpts
```

2. Нажми `Create` или `+ Create`.

3. Откроется GPT Builder. Обычно там есть две вкладки:

- `Create` - можно словами описать, какого GPT ты хочешь;
- `Configure` - ручная настройка.

4. Перейди в `Configure`.

5. Заполни основные поля:

```text
Name: Мир Меча и Магии Lore
Description: Помогает генерировать портреты и сцены по лору кампании.
```

6. В `Instructions` вставь содержимое файла:

```text
lore_api/CUSTOM_GPT_INSTRUCTIONS_SHORT.md
```

Это короткая версия инструкций, рассчитанная на лимит поля `Instructions`.

Полная версия лежит здесь:

```text
lore_api/CUSTOM_GPT_INSTRUCTIONS.md
```

Ее можно прикрепить в Custom GPT как файл знаний, если хочется сохранить весь подробный регламент рядом с GPT.

Отдельный промпт для генерации сцен через Codex:

```text
lore_api/CODEX_SCENE_GENERATION_PROMPT.md
```

Он рассчитан на работу с локальным репозиторием, Markdown-каноном, портретами в `11_Медиа` и Google Drive с уже созданными сценами.

Для более строгого пошагового процесса можно использовать оркестратор и отдельных агентов:

```text
lore_api/codex_agents/ORCHESTRATOR.md
```

Агенты разделены на сбор лора и ссылок, написание промпта сцены и генерацию изображения.

7. В `Capabilities` включи `Image Generation`, если GPT должен создавать изображения.

8. `Web Search` лучше выключить, чтобы GPT не искал лор в интернете вместо Lore API.

9. `Canvas` можно оставить включенным, если хочешь редактировать длинные промпты и описания сцен в отдельной панели.

10. `Code Interpreter & Data Analysis` для генерации по лору обычно не нужен.

11. Пока не публикуй GPT публично. Для личного использования при публикации выбирай приватный вариант.

После этого можно подключать Lore API через `Actions`.

### Если GPT игнорирует инструкции

Иногда Custom GPT не вызывает Action сам, особенно если запрос звучит как обычная просьба к чату или сразу просит изображение. Чтобы снизить это, в инструкции добавлен hard gate: для любого запроса по миру первым действием должен быть вызов Lore API. Без API запрещено отвечать по существу, писать промпт и запускать image generation.

Проверь настройки:

- `Instructions` действительно содержит текст из `lore_api/CUSTOM_GPT_INSTRUCTIONS_SHORT.md`;
- `Actions` подключены и схема `/openapi.json` сохранена без ошибок;
- `Web Search` выключен;
- в первом сообщении можно писать прямо: "Первым действием вызови Lore API. Не генерируй изображение до get_character и get_references".

Если GPT все равно ответил без API, напиши: "Ты нарушил HARD REQUIREMENT: вызови Lore API и переделай". По текущим инструкциям он должен не спорить, а сразу перепроверить запрос через Actions.

## Как подключить Lore API к Custom GPT

К этому шагу у тебя уже должен быть публичный HTTPS-адрес Lore API. Например:

```text
https://lore-api.example.com
```

После публикации сервиса:

1. Открой настройки своего Custom GPT.
2. Перейди в Actions.
3. Добавь новую Action.
4. Укажи схему:

```text
https://lore-api.example.com/openapi.json
```

После этого Custom GPT сможет вызывать методы API и получать лор из репозитория.

## Что отдавать генератору изображений

Для портретов и сцен ChatGPT должен брать:

- текстовую карточку персонажа из `/characters/{name}`;
- metadata визуальных референсов из `/references/{character}`;
- контекст сцены из `/scene-context`;
- портреты, уже сгенерированные сцены и сюжеты кампании из Google Drive:
  `https://drive.google.com/drive/folders/1vaVpCHYNYaj6rJvmw45LUjc-C31SzuPI?usp=sharing`;
- запасную ссылку на главный портрет через `download_url` из `references`, если Drive-ссылка не найдена.

В базе не хранятся сами картинки. API хранит и отдает пути, описания и ссылки.

Практическая схема теперь такая:

```text
Lore API      -> персонажи, лор, scene context, references metadata
Google Drive  -> портреты, сцены, сюжеты кампании, actual image references
scene_name    -> название папки сцены/сюжета на Google Drive
Пользователь  -> вручную прикрепляет найденные изображения в чат, если GPT не может загрузить их сам
ChatGPT Plus  -> image generation использует прикрепленные изображения
```

Почему так: Custom GPT Actions хорошо получает JSON и ссылки, но ссылка на PNG или Google Drive сама по себе не всегда становится для генератора настоящим visual reference. Если среда GPT умеет открыть и загрузить изображение с Google Drive как image input, он должен использовать его. Если нет, надежный способ в ChatGPT Plus - вручную прикрепить найденный портрет или сцену в чат.

GPT должен после `/references` показать пользователю ссылки на главные портреты и попросить прикрепить их перед словом "Генерь". Если GPT пишет промпт сцены, то сразу после промпта он должен отдельным блоком прислать ссылки на нужные портреты, если пользователь еще не прикрепил их в чат.

Если первое сообщение пользователя содержит `scene_name`, GPT должен использовать его как название папки сцены или сюжета на Google Drive. Нужно найти такую папку, добавить найденные там сцены/изображения в контекст и учитывать порядок, если в названиях есть нумерация.

### Как просить портреты

Пример сообщения GPT перед генерацией:

```text
Я нашел главный портрет:
Великий Шах Саладин - https://...ngrok-free.dev/files/...

Прикрепи этот портрет в чат как изображение, затем напиши "Генерь".
```

Если персонажей несколько, GPT должен дать ссылку на основной портрет каждого важного персонажа.

## Частые проблемы

### `python3: command not found`

Python не установлен или не добавлен в PATH. Нужно установить Python 3.9 или новее.

### `pip install` не работает

Чаще всего нет интернета, заблокирован доступ к PyPI или не активировано окружение. Проверь, что перед командной строкой есть `(.venv)`.

### `Address already in use`

Порт `8010` уже занят. Можно запустить на другом порту:

```bash
uvicorn lore_api.app:app --host 127.0.0.1 --port 8011
```

Тогда адрес будет:

```text
http://127.0.0.1:8011
```

### `index_exists:false`

Индекс еще не собран. Выполни:

```bash
python -m lore_api.indexer
```

### ChatGPT не видит локальный API

Это нормально: `127.0.0.1` виден только на твоем компьютере. Для ChatGPT нужен публичный HTTPS-адрес.
